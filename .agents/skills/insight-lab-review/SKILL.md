# Insight Lab 검수

1. 저장소 루트의 `docs/Insight_Lab_Requirements_v1.0.md`에서 대상 서비스의 세부 조항과 완료 기준을 읽는다. 범위가 충돌하면 `docs/Insight_Lab_Requirements_Audit_v1.0.md`의 최종 기준을 적용한다. `docs/v1-implementation-check.md`의 과거 집계는 현재 코드와 대조할 출발점으로 사용한다.
2. 화면이 소비하는 `data/` 파일과 집계 코드를 따라가서 자료의 기준일, 단위, 분모와 누락 범위를 확인한다. 예를 들어 두 미국 ETF의 수록 기간은 월 키의 합집합으로 세고, 증권사 이익은 연결·별도 및 연간·분기 누적을 구분한다. 로컬에서만 산출한 결과와 방문자에게 공개한 결과를 각각 기록한다.
3. 해당 서비스에서 대표 경로 하나를 끝까지 확인한다. 월간 순위라면 월 선택 → 종목·수익률 → 산출 기준·출처 순으로 살핀다. UI가 바뀌면 모바일과 데스크톱에서 영향을 받는 조작을 검사한다. 기능이나 게시 데이터 변경에는 AGENTS.md의 린트·타입·테스트·빌드 검증을 적용한다.
4. 점검만 요청받으면 확인한 근거와 남은 작업을 우선순위대로 보고한다. 개발 요청이면 범위 안의 결함을 수정하고 해당 경로를 재검증한다. 배포 요청이 있으면 발행 완료 후 대상 운영 경로에서 이번 변경을 식별할 수 있는 값이나 동작을 확인한다.
